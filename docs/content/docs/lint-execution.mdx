`gavel lint` discovers native tool configuration and project signals, runs selected linters concurrently, and reports their findings together. Keep tool rules in the tool's native configuration; use `.gavel.yaml` for orchestration, runtime limits, and explicit tool selection.

```bash
gavel lint
gavel lint --dry-run
gavel lint golangci-lint ./pkg/parser
gavel lint --linters eslint,tsc ./web
```

## Supported tools

<DocChildren parent="lint-execution" />

| Area | Linters |
| --- | --- |
| Go | `golangci-lint` (alias `golangci`) |
| Python | `ruff`, `pyright` |
| JavaScript and TypeScript | `eslint`, `oxlint`, `tsc` (alias `typescript`) |
| React | `react-doctor`, activated by a React dependency |
| Markdown and prose | `markdownlint`, `vale` |
| JSON, YAML and NDJSON | `json`, with optional JSON Schema validation |
| Duplicate code | `jscpd` |
| Secrets | `betterleaks` (alias `secrets`) |

Detection depends on each tool's native configuration or signal, such as `tsconfig.json` or a React dependency in `package.json`. `--linters` restricts execution and rejects unknown names. `jscpd` can be enabled explicitly through project settings. Use `--dry-run` to see which commands your repository will execute.

## Scope findings and compare runs

```bash
gavel lint --changed
gavel lint --since origin/main
gavel lint --baseline .tmp/main.json
gavel lint --failed
gavel lint --failed .tmp/previous.json
gavel lint --pr 12
gavel lint --ignore "**/generated/**"
gavel lint uir --exclude small-single-declaration-file
gavel lint --exclude 'uir:small-*,eslint:no-debugger'
```

`--changed` selects staged, unstaged and nonignored untracked files locally, or the runner's changeset in CI. `--since HEAD` selects local edits; `--since staged` selects staged files while inspecting current contents; another ref selects its merge-base diff plus local edits. Lint reports all findings in selected files. See [Changed code](/docs/change-selection) for CI setup, explicit files and comparison rules.

A linter may answer from its own cache when its inputs are unchanged; the result then says how old it is, and `--no-lint-cache` forces a fresh run. See [Cached lint results](/docs/lint-caching).

`--baseline` removes findings already represented in a saved report. Baseline matching uses linter, file, and rule, so moving a line does not make the same finding new. It also means multiple findings of the same rule in one file share that identity.

`--failed` selects linters and files with previous violations, using `.gavel/last.json` when no file is specified. `--pr` uses a PR's Gavel artifacts. Keep an explicit snapshot when reproducing a specific CI failure.

Explicit `--failed` and `--baseline` files must be saved snapshot objects. Standalone `gavel lint --json` exports an array for analysis; that array is not a rerun baseline. After a lint run, copy the snapshot named by `.gavel/last.json` as shown in [Reporting](/docs/reporting).

`--exclude` selects rule IDs, while `--ignore` selects file globs. Repeat `--exclude` or comma-separate selectors. Matching is case-sensitive; `*` matches any part of a reported rule ID, including `/`. Use `source:rule` to target one linter, such as `oxlint:eslint/no-debugger`; source aliases such as `golangci`, `secrets` and `typescript` are accepted. Empty selectors and unknown sources fail before tools run.

Every selector filters findings before task verdicts, snapshots, summaries, JSON, UI results and AI repair. Exclusions remain active during UI reruns and AI-fix iterations. Execution failures and timeouts still fail even when no findings remain. Prompt lint also supports rule exclusions, including `prompt:rule-id`.

Gavel also disables native rules for UIR, golangci-lint, Ruff, ESLint and Oxlint when a selector has an equivalent native representation. Qualified selectors route only to their source. Bare selectors route natively when one linter is selected; in multi-linter runs they filter findings across tools. Native disabling supports exact IDs, plus Ruff's trailing rule-prefix wildcard such as `ruff:F4*`. Other wildcard selectors and unsupported adapters filter findings after execution. Oxlint category shortcuts such as `all` are not treated as rule IDs. Use `--dry-run` to inspect the native arguments.

## Prompt-based linting

`gavel lint prompt [name|id|file] [path...]` runs a Captain prompt with the built-in `Lint` preset. It accepts Captain prompt names and IDs, `.prompt` files, inline `--prompt/-p` text, stdin, template variables, presets, and model overrides. The selected prompt controls what is reviewed; pass file contents or a diff through variables or stdin, or pass paths to scope the review.

```bash
gavel lint prompt examples/lint-review.prompt --model agent:sonnet
gavel lint prompt review.prompt ./pkg cmd/main.go --model agent:sonnet
gavel lint prompt review.prompt --changed ./pkg --ai-fix
git diff | gavel lint prompt examples/lint-review.prompt --model api:sonnet
git diff | gavel lint prompt review.prompt -V change=- --model api:sonnet
gavel lint prompt -p "Review the current change for correctness" --since main --model agent:sonnet
gavel lint prompt examples/lint-review.prompt --dry-run --json
```

Arguments after the prompt are files or directories; with `-p` every argument is a path. `--changed`, `--since` and `--changed-files` narrow that scope to changed files exactly as they do for `gavel lint`, and a selection with no changed files skips the model call. Gavel passes the scope to the prompt as the `files` template variable (space-separated paths relative to the working directory, the convention Captain's built-in review prompts use), so reference `{{files}}` in the template. Passing `-V files=…` or a `files` key in `--vars` alongside a scope is an error.

`--ai-fix` repairs prompt findings with `lint.fix` from Gavel config, then reruns the same prompt over the same scope until it is clean or `--ai-fix-max-iterations` (default 3) is reached. On this command `--model` and the other runtime flags configure the reviewing prompt, not the fixer. Piped stdin is replayed to each rerun.

The preset supplies a JSON output schema with a required `violations` array. Each violation requires `message` and can include `file`, `line`, `column`, `rule` (with `method` and `package`), `severity`, `source`, and `code`. Return `{"violations": []}` for a clean review. Relative file paths resolve against the prompt's working directory. Errors and omitted severities fail lint; warnings and informational findings retain the normal lint verdicts. Invalid output and failed prompt executions fail the command.

Prompt runs use normal lint snapshots and support `--summary`, `--summary-limit`, and global output formats. `--multi-models` produces separate lint results for each runtime, preserving findings when another runtime fails. `--dry-run` renders the effective prompt and schema without calling a model.

Captain presets have an integer `order` (default `0`). Layers merge in ascending order, then scope, then selection order for ties. The built-in lint preset uses `order: 100`, so its output schema overrides ordinary prompt declarations. `--preset` selects additional review settings; `--no-presets` clears prompt-selected presets while retaining the lint preset. The same output contract is available directly with `captain prompt run review.prompt --preset lint`.

## Native fixes and AI repair

```bash
gavel lint --fix
gavel lint --ai-fix --ai-fix-max-iterations 3
```

`--fix` asks supported native tools to edit source. `--ai-fix` runs the configured `lint.fix` agent and reruns lint until clean or its iteration limit is reached. AI repair needs a configured model runtime. `-y` implies AI repair, so it is an editing operation. Run plain `gavel lint` to inspect findings first.

Reporting-only exclusions do not prevent a native tool from applying `--fix` edits for those rules. Native rule disabling prevents their execution where supported.

`--triage` is an interactive operation that can persist lint-ignore rules. Project ignore rules match all populated `rule`, `source`, and `file` fields; an empty rule matches nothing. The complete rule format is included in the [Configuration reference](/docs/configuration-reference).

## Runtime settings

```yaml
lint:
  runtime:
    timeout: 3m
    mem: 1GiB
  linters:
    eslint:
      args: ["--max-warnings=0"]
    jscpd:
      enabled: true
```

Within a config layer, `runtime` precedes `lint.runtime`, which precedes `lint.linters.<name>.runtime`; later config layers and explicit invocation options win. `args` supplies native arguments, and `enabled` forces a tool on or off. `gavel lint --timeout 2m` sets a deadline for each linter invocation. Use `--no-lint-cache` to bypass result caching during diagnosis.

Secret-scanning rules stay in `.betterleaks.toml` or `.gitleaks.toml`. Gavel discovers and merges those files; `secrets.configs` names additional files, and `secrets.disabled` controls scanner activation.

## Limit linters run outside gavel

```bash
gavel lint install-shims --timeout 30s --cpu-limit 200 --mem-limit 2GB
export PATH="$HOME/.gavel/shims:$PATH"
```

`install-shims` writes PATH shims for `golangci-lint`, `eslint` and `tsc`, so editors and agents that call these tools directly get bounded runs. With a shim in place:

- `golangci-lint run` gets `--fast-only`, `--concurrency` and `--allow-parallel-runners`, so concurrent runs don't queue on golangci-lint's per-user lock.
- `eslint` gets a cache kept outside the repository.
- Each shimmed linter's parallelism (`GOMAXPROCS`, `UV_THREADPOOL_SIZE`) and memory (`GOMEMLIMIT`, `--max-old-space-size`) are capped from the limits.

Each linter is niced. It is killed with exit 124 after the timeout, and with exit 137 when it stays above the CPU limit or exceeds the memory limit. Explicit flags such as `--fast-only=false` or `--no-cache` are respected. `GAVEL_SHIMS=off` bypasses a shim. `gavel lint` always resolves the real binaries behind the shims.

## Report and combine with tests

```bash
mkdir -p .tmp
gavel lint --summary --summary-limit 3
gavel lint --format "json=.tmp/lint.json,markdown=.tmp/lint.md"
gavel lint --ui --addr localhost
gavel test --lint --format "json=.tmp/checks.json,html=.tmp/checks.html"
```

Summary output groups findings by linter and rule with a limited set of example locations. JSON retains structured detail. Combined test runs include `lint_results` in the test snapshot. See [Reporting](/docs/reporting) for the distinction between standalone lint JSON and combined test JSON, and [Runner steps](/docs/fixture-runner-steps) to use lint as a fixture gate.

## Command options

| Flag | Description |
|------|-------------|
| `[linters/files...]` | Positional args: linter names run only those linters; file paths lint only those files |
| `--linters` | Comma-separated linter names or `*` for all (default: `*`) |
| `--fix` | Enable auto-fixing |
| `--triage` | Interactive mode to select violation types to ignore (saves to `.gavel.yaml`) |
| `--changed` | Lint local staged/unstaged/untracked files, or the runner changeset in CI |
| `--since` | Select a ref's merge-base diff plus local edits; `HEAD` selects local edits, `staged` selects staged files |
| `--changed-files` | Explicit changed files; union with another supplied change selector |
| `--ignore` | Glob patterns to exclude from linting |
| `--exclude` | Exclude rule IDs or `*` patterns, optionally qualified as `source:rule`; repeat or comma-separate |
| `--ui` | Launch browser UI to view violations |
| `--addr` | Interface to bind the UI server (default: `0.0.0.0`, all interfaces; set `localhost` to restrict to this machine) |
| `--no-cache` | Disable caching/debounce |
| `--timeout` | Timeout per linter (default: `5m`) |
| `--dry-run` | Print linter commands without executing |
