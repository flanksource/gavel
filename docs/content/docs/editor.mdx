---
title: Browser editor
description: Edit local Markdown, MDX, JSON and YAML files with schema forms and manual lint.
---

Run `gavel edit` with one or more existing files or folders. Gavel starts a local server, prints its URL, and opens the browser. Stop it with Ctrl+C.

```sh
gavel edit docs configs/settings.yaml
gavel edit configs --schema ./schemas/settings.json
gavel edit README.md --port 9095 --no-open
```

Folders are searched recursively for `.md`, `.mdx`, `.json`, `.yaml`, and `.yml` files, respecting Git ignores. Explicitly named files are included even when ignored. Cmd+K or Ctrl+K searches names and paths. The selected file is kept in the URL.

Source edits autosave after 600 milliseconds, including incomplete syntax. Save status and errors stay visible. Conflicting disk edits stop autosave until you reload or explicitly replace the disk content with your draft. Closing the page with pending or failed saves prompts before leaving.

Markdown and MDX offer rich text editing alongside source mode. JSON/YAML files and Markdown frontmatter offer a schema form when a schema is available. For Markdown, the frontmatter form also sits in a collapsible **Properties** panel above the rich text body, so a page's properties and content are edited together; editing a property on a page without frontmatter adds the `---` block. Schemas resolve as for the [json linter](/docs/linter-json): `--schema` overrides declarations; otherwise a `$schema` key or YAML language-server header, then the file's [`lint.schemas`](/docs/configuration-reference#lint) glob, then gavel's built-in schema for fixture files. `--schema` resolves local paths from the command's working directory. Local and HTTP(S) references are loaded by Gavel. Schema failures remain visible and source editing remains available. Structured edits retain unknown fields, YAML comments, anchors, and aliases. Editing an anchored value updates its aliases; editing an alias independently detaches that occurrence. Cyclic aliases cannot be represented in a form and require source editing. Opening a form does not apply schema defaults or save changes.

The editor opens with the problems the workspace's recorded runs (`.gavel/run-*.json`) hold for the selected files: lint violations and failed tests, such as a failing fixture step in a Markdown file. Each file's lint violations come, per linter, from the newest run that linted it, so linting one file replaces only that file's results. Current `.gavel.yaml` ignore rules apply. A file changed after the run that checked it, or edited in the editor, is marked stale.

Use **Lint file**, **Lint folder** or **Lint all files** to run applicable Gavel linters with the selected repositories' configuration. Pending saves finish before lint starts. The run is saved to `.gavel` like a `gavel lint` run limited to those files, so `gavel ui serve`, `gavel lint --failed` and the next `gavel edit` see it. Findings include file locations and execution failures. Editing and autosaving do not start lint, and the editor does not automatically fix findings.

While the editor is open, `gavel test` and `gavel lint` runs started in the same workspace show their progress in the status line, and the problems reload when they finish.

The server binds to loopback and only edits the selected files. It does not require the PR dashboard, PostgreSQL, or GitHub authentication. File creation, deletion, renaming, and remote hosting are outside this command.
