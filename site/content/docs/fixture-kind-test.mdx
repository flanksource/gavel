Use the `test` step to execute native test suites as a fixture step.

## Example

```yaml
kind: Fixture
name: Test example
steps:
  - id: regressions
    kind: test
    paths: [./pkg/parser]
    framework: [go]
    test-timeout: 2m
    show-passed: true
```

Save the document as a `.fixture.yaml` file. Inspect it with `gavel fixtures outline <file>`, then execute it with `gavel fixtures <file>` once its prerequisites are available.

## Configuration and prerequisites

Keys use test CLI spelling, with `paths` replacing positional arguments. Choose framework names from [Test execution](/docs/test-execution), and use real package paths. Embedded test steps do not recurse into fixture discovery or launch a separate UI.

## Results and lifetime

Runner results become children of this step. Available summary outputs include `total`, `passed`, `failed`, `warned`, and `skipped`; the run artifact points to the full snapshot. A failed suite fails the fixture verdict.

The Markdown equivalent is a `yaml test` fence. See [Runner steps](/docs/fixture-runner-steps) for embedding behavior.
