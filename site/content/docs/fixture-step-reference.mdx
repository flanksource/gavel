YAML and JSON fixtures declare `kind: Fixture` and a nonempty `steps` array. Steps execute in authored order; each selects a registered kind with `kind`. Unknown fields and invalid kind configuration fail validation. Markdown command and runner fences use the same execution engine.

```yaml
kind: Fixture
name: CLI contract
env:
  MESSAGE: ready
steps:
  - id: message
    kind: exec
    exec: printf
    args: ["%s", "$MESSAGE"]
    cel: stdout == "ready" && exitCode == 0
```

Save it as `checks.fixture.yaml`, then inspect and run it:

```bash
gavel fixtures outline checks.fixture.yaml
gavel fixtures checks.fixture.yaml
```

The JSON equivalent uses the same keys. Explicit discovery globs are needed to include these extensions in `gavel test`.

Download runnable examples in [YAML](/examples/smoke.fixture.yaml) and [JSON](/examples/smoke.fixture.json). Both require only `printf` and exercise environment expansion and CEL assertions.

## Step vocabulary

| Kind | Use |
| --- | --- |
| `exec` | Execute a command or script and assert on its streams and exit code |
| `test` | Run the test engine with typed runner options |
| `lint` | Run the lint engine with typed runner options |
| `ai` | Evaluate a prompt and checklist with a configured grader |
| `services` | Provision fixture services and manage their readiness and lifetime |
| `browser` | Start a browser session and expose connection details |
| `agent-browser` | Execute browser automation commands against a session |
| `playwright` | Run the registered Playwright fixture integration |
| `todo` | Create, get, or review a TODO through the dashboard API |
| `todo_prompt` | Dispatch a TODO lifecycle step and inspect its result |

Each kind's dedicated page includes prerequisites, a document example, output behavior, and its complete field reference. Browser and service fixtures need the tools and runtime required by their selected kind. TODO kinds need a reachable dashboard and its configured workspace.

## Outputs and exports

Give a step an `id` when later assertions need its result. CEL can read earlier outputs through `steps.<id>`, current kind outputs, and the fixture environment. `export` projects outputs into environment variables for later steps; values use Go templates such as `{{.outputs.url}}`. Re-exporting an existing name requires explicit `override: true`. `"*"` exports a map and an empty export value suppresses a kind's default export.

## Waits, retries, and background lifetime

`wait` polls a kind's observable state until `until` evaluates true or its timeout expires. `failWhen` ends polling early with a failure. Only kinds that implement observation accept waits. Interval, backoff, and jitter bound polling without needing a separate shell sleep loop.

`retry` reruns execution according to `attempts`, `when`, delay, backoff, and jitter. This is distinct from polling an already-running resource. `defaults` supplies document-wide timeout, wait, and retry settings; steps can refine those settings. `background: true` keeps a supported step running for the fixture lifetime and collects its verdict at teardown.
