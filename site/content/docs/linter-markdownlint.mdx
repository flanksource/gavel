## Detection and native configuration

Detection input: `.markdownlint.json`, `.markdownlint.jsonc`, `.markdownlint.yaml`, `.markdownlint.yml`, or `.markdownlint-cli2.*`. Explicit selection pins this tool; matching source files and an available executable are still required. Inspect planned commands before execution:

```bash
gavel lint markdownlint --dry-run
gavel lint markdownlint
gavel lint markdownlint --changed
```

The adapter invokes the `markdownlint` command and normalizes its diagnostics. Keep Markdown rule settings in the native config.

## Configure execution

```yaml
lint:
  linters:
    markdownlint:
      enabled: true
      runtime:
        timeout: 2m
        mem: 1GiB
```

`lint.linters.markdownlint.args` supplies native tool arguments. Process settings inherit from `runtime` and `lint.runtime`; explicit invocation settings take precedence. Native rule configuration is separate from these Gavel orchestration fields.

## Findings and reruns

```bash
mkdir -p .tmp
gavel lint markdownlint --format "json=.tmp/markdownlint.json,markdown=.tmp/markdownlint.md"
gavel lint markdownlint --failed
```

Standalone lint JSON is an array of tool results. For an explicit rerun or baseline, save the snapshot named by `.gavel/last.json`, as shown in [Reporting](/docs/reporting). Changed and baseline filters affect which findings are reported, and do not necessarily narrow native analysis to the same files. See [Lint execution](/docs/lint-execution) for common filters and repair behavior.
