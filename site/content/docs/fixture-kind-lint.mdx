Use the `lint` step to run selected linters as an executable fixture gate.

## Example

```yaml
kind: Fixture
name: Lint example
steps:
  - id: source_checks
    kind: lint
    files: [./pkg/parser]
    linters: [golangci-lint]
    timeout: 2m
```

Save the document as a `.fixture.yaml` file. Inspect it with `gavel fixtures outline <file>`, then execute it with `gavel fixtures <file>` once its prerequisites are available.

## Configuration and prerequisites

Keys use lint CLI spelling, with `files` replacing positional arguments. Native tool configuration stays in its own files. Embedded steps exclude interactive triage and source-repair options; use them to report findings and enforce a gate.

## Results and lifetime

Tool findings appear as child results and a persisted run artifact links to full evidence. Summary outputs include test-style counts and `lintViolations`. Tool errors and violations are distinct evidence within the step.

The Markdown equivalent is a `yaml lint` fence. Dedicated tools are indexed in [Lint execution](/docs/lint-execution).
