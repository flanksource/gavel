`gavel lint` and `gavel test` use the same changeset resolver. Ordinary runs check everything; a change selector narrows the run. `gavel test --lint --changed` shares one resolved changeset between both engines.

```bash
gavel test --changed --dry-run
gavel test --lint --changed
gavel lint --since staged
gavel test --since HEAD
gavel lint --since origin/main
gavel test --changed-files pkg/service.go
```

| Selector | Files selected |
| --- | --- |
| `--changed` locally | Staged, unstaged and nonignored untracked files. Committed branch changes are excluded. |
| `--changed` in CI | The runner's PR/MR comparison or push range. Generated and otherwise uncommitted files are excluded. |
| `--since HEAD` | Staged, unstaged and nonignored untracked files, including in CI. |
| `--since staged` | Staged files only. Checks inspect their current working-tree contents, including any additional unstaged edits in those files. |
| `--since <ref>` | Changes from the ref's merge-base with HEAD through HEAD, plus staged, unstaged and nonignored untracked files. |
| `--changed-files <paths>` | Explicit files, with no Git change discovery required. Combined selectors union these files with their changeset. |

Explicit `--since` overrides automatic selection. `GAVEL_CHANGED_BASE` provides an explicit ref override for `--changed`. A branch named `staged` can be selected as `--since refs/heads/staged`. Positional paths further restrict discovery and lint reporting.

Lint reports all findings in changed files, including findings on unchanged lines. Native configuration and project manifest changes expand the affected project's scope. Project-wide analyzers can inspect more code; findings are filtered before task status and reporting. Native tools receive applicable file arguments when safe; golangci-lint retains full module context. Execution failures and diagnostics without a file remain visible. Native `--fix` can edit outside the reporting scope when the adapter must run project-wide.

Go tests select the containing packages and their reverse dependencies, including test imports. Module/workspace changes invalidate affected package graphs. Other frameworks and standalone fixtures run conservatively when the changeset is nonempty; there is no JavaScript dependency graph. A valid selection with no applicable work succeeds with zero executed checks and an explicit skip message.

## CI comparisons

GitHub Actions uses its event payload for PR source/base commits, push before/after commits and merge groups. Azure Pipelines uses PR source/target metadata or the built commit. GitLab uses MR diff-base and merged-result metadata or push before/after commits. Source checkouts and verified synthetic merge checkouts are supported; the checked-out tree is always the tree analyzed.

Without a supplied previous SHA, a non-PR job compares the built commit with its first parent. A genuine root commit compares against an empty tree. Invalid metadata, unrelated checkouts, missing commits and shallow history fail with an actionable error. Gavel does not fetch history or call hosting APIs. An unsupported CI runner must supply `--since` or an explicit comparison through the Go API.

The workflow must check out the source or merge commit, target refs, and sufficient history. These minimal examples disable shallow checkout; they do not publish artifacts or comments.

### GitHub Actions

```yaml
on: [push, pull_request]
jobs:
  checks:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: flanksource/gavel@main
        with:
          args: test --lint --changed
          comment: false
```

### Azure Pipelines

Install Gavel on the agent before the script step. PR checkouts also need the target branch available under `refs/remotes/origin/`; configure the checkout's refspec accordingly if your runner only fetches the PR ref.

```yaml
steps:
  - checkout: self
    fetchDepth: 0
  - script: gavel test --lint --changed
    displayName: Check changed code
```

### GitLab CI

Use a runner image with Gavel and the project's test tools installed.

```yaml
variables:
  GIT_DEPTH: "0"
checks:
  script:
    - gavel test --lint --changed
```

## Reuse and inspection

The Go package `github.com/flanksource/gavel/git/changeset` exposes `Resolve`, selection options, injectable providers, explicit comparisons and a per-invocation `Selection`. `Selection.Fresh()` preserves the selector while resolving new state for reruns. Repository-relative paths retain rename origins and deletions; deleted paths are not passed as native input files.

Dry runs print the provider, mode, resolved comparison and file count. Saved snapshots include changeset provenance under `metadata.changes`. UI reruns and AI repair iterations resolve fresh state rather than retaining an earlier local file set.
