## File locations and precedence

Gavel loads built-in defaults, the home-directory config, the Git-root config, and the selected target-directory config, in that order. A file target uses its parent directory. Each physical config is loaded once. This is a fixed set of locations, rather than a walk through every ancestor directory.

```bash
gavel config
gavel config ./pkg/parser
gavel config ./pkg/parser/parser.go --json
gavel config --resolve --json
gavel config --runtime --json
```

Plain `config` shows the merged settings and contributing sources. `--resolve` adds registered AI prompts, effective specs, and provenance. `--runtime` inspects per-tool process settings and environment variable names.

## Editor validation

Add this comment to `.gavel.yaml` for YAML language-server completion and validation:

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/flanksource/gavel/main/gavel.schema.json
fixtures:
  enabled: true
  files: ["tests/**/*.fixture.md"]
test:
  timeout: 20m
  testTimeout: 5m
lint:
  runtime:
    timeout: 3m
```

## Merge behavior

AI and prompt specs merge field by field. Runtime environment maps merge by key, while nonempty native argument lists replace earlier lists. Hooks and lint-ignore rules append in layer order. Commit ignore/allow lists and additional secret config paths append and deduplicate. Fixture globs replace an earlier nonempty list; fixture enablement is sticky once enabled. Explicit per-linter `enabled` values can override earlier values.

Within each runtime layer, global settings precede category settings and then the named framework or linter. Later files and explicit caller settings take precedence. Empty environment values clear inherited values; `cpu: 0` and an empty memory limit disable their inherited caps. Runtime invocation deadlines and the whole-run test deadline are distinct.

Gavel runtime loading and editor schema validation are separate checks. Retired fields marked deprecated do not restore old behavior; migrate to their replacement. See [Runtime presets](/docs/todo-runtime-profiles) and [Prompt overrides](/docs/prompt-overrides).
