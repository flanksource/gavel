Fixture integration runs document-based checks alongside native frameworks. It uses the same engine as `gavel fixtures`, with fixture results attached to the test report.

## Discovery

```yaml
fixtures:
  enabled: true
  files:
    - "tests/**/*.fixture.md"
    - "tests/**/*.fixture.yaml"
    - "tests/**/*.fixture.json"
```

The default glob is `**/*.fixture.md`. YAML and JSON require explicit discovery patterns. A nonempty `fixtures.files` list replaces earlier lists.

## Execute

```bash
gavel test --fixtures
gavel test --fixtures --fixture-files "tests/**/*.fixture.md"
gavel fixtures checks.fixture.yaml
```

Use `gavel test --fixtures` for combined reports and `gavel fixtures` for directly named files. This adapter is selected through fixture options rather than a `gavel test fixture` subcommand.

## Runtime configuration

```yaml
test:
  frameworks:
    fixture:
      runtime:
        timeout: 2m
        mem: 1GiB
```

`test.frameworks.fixture.args` passes extra arguments to exec steps. A fixture's own execution settings and assertions remain in the fixture file. See [Test execution](/docs/test-execution) for whole-run controls and [Reporting](/docs/reporting) for artifacts.

## Author checks

Start with [Fixture overview](/docs/fixtures-overview). [Fixture file reference](/docs/fixture-reference) describes frontmatter and fences; [Fixture step reference](/docs/fixture-step-reference) indexes every typed step kind. Embedded test steps disable recursive fixture discovery.
