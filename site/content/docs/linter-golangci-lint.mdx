## Detection and native configuration

Detection input: `.golangci.yml`, `.golangci.yaml`, `.golangci.toml`, or `.golangci.json`. Explicit selection pins this tool; matching source files and an available executable are still required. Inspect planned commands before execution:

```bash
gavel lint golangci-lint --dry-run
gavel lint golangci-lint
gavel lint golangci-lint --changed
```

Alias: `gavel lint golangci`. Rule configuration stays in golangci-lint's native file; Gavel scopes execution, applies reporting filters, and normalizes findings.

## Configure execution

```yaml
lint:
  linters:
    golangci-lint:
      enabled: true
      runtime:
        timeout: 2m
        mem: 1GiB
```

`lint.linters.golangci-lint.args` supplies native tool arguments. Process settings inherit from `runtime` and `lint.runtime`; explicit invocation settings take precedence. Native rule configuration is separate from these Gavel orchestration fields.

## Findings and reruns

```bash
mkdir -p .tmp
gavel lint golangci-lint --format "json=.tmp/golangci-lint.json,markdown=.tmp/golangci-lint.md"
gavel lint golangci-lint --failed
```

Standalone lint JSON is an array of tool results. For an explicit rerun or baseline, save the snapshot named by `.gavel/last.json`, as shown in [Reporting](/docs/reporting). Changed and baseline filters affect which findings are reported, and do not necessarily narrow native analysis to the same files. See [Lint execution](/docs/lint-execution) for common filters and repair behavior.
