Gavel is a single CLI that runs your tests, linters, and declarative Markdown fixtures — locally and in CI.

## Install

The CLI is a single Go binary. The easiest install is through the Go toolchain:

```bash
go install github.com/flanksource/gavel/cmd/gavel@latest
```

Prefer a prebuilt binary? Download a release from [the releases page](https://github.com/flanksource/gavel/releases) and drop it in your `$PATH`.

<Callout variant="tip" title="Shell completion">
  Run `gavel completion --help` to generate completion scripts for bash, zsh, fish, or PowerShell.
</Callout>

## Run tests

From the root of any Go project:

```bash
gavel test
gavel test --lint --format "json=tests.json,html=tests.html"
```

Gavel discovers test suites and runs their native engines. The second command combines tests and detected linters and explicitly writes JSON and HTML reports. See [Test execution](/docs/test-execution) for Go, Ginkgo, Jest, Vitest, Playwright, and fixture discovery, and [Reporting](/docs/reporting) for output formats and run history.

## Lint in parallel

```bash
gavel lint
```

Supported linters (activated when their native config or project signal is discovered):

- **Go**: golangci-lint
- **Python**: ruff, pyright
- **TypeScript/JavaScript**: eslint, oxlint, react-doctor (React dependency), tsc
- **Markdown & prose**: markdownlint, vale
- **Cross-cutting**: jscpd (duplicate code), betterleaks (secrets)

All run concurrently and merge into a single report.

## Run declarative fixtures

```bash
gavel fixtures checks.fixture.md
```

Fixtures combine Markdown tables, executable command blocks, test/lint runner steps, CEL assertions, and optional AI review steps. YAML and JSON fixtures can also orchestrate services, browsers, and TODO lifecycle steps. TODO definitions of done use the same fixture engine.

## Inspect configuration

```bash
gavel config
gavel config --runtime --json
gavel fixtures --schema
```

Use the [Configuration reference](/docs/configuration-reference) for every `.gavel.yaml` field and the [Fixture file reference](/docs/fixture-reference) for fixture frontmatter and runner options.

## Track work with TODOs

```bash
gavel todos create --title "Fix parser error messages" --body @todo.md --verification @verification.md
gavel todos list
gavel todos steps 90ec80f0
gavel todos run 90ec80f0 --step plan --dry-run
```

Create `todo.md` and `verification.md` with your task and runnable checks first, and replace `90ec80f0` with the created reference. TODOs use a PostgreSQL workspace. Planning, approval, implementation, and verification are covered in [Todo engine](/docs/todo-engine) and [Todo run loop](/docs/todo-run-loop).
