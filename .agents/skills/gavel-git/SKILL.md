# Gavel Git & PR Workflow

Reach for `gavel` — not raw `gh` or `git commit` — for pull requests, CI status,
and commits. Gavel renders workflow steps, conclusions, timing, and failing-step
logs in one view, generates conventional commit messages and PR content with an
LLM, and can send CI failures directly to an agent. Reserve raw `gh`/`git` only
for actions gavel does not cover.

`--help` is the source of truth for flags. Start with `gavel pr --help` and
`gavel commit --help`; this skill is the *when/why* + a cheatsheet.

## When to use

- "check the PR", "why is CI failing", "what failed on the PR", "is the PR green"
- "open a PR", "push and open a PR", "raise a PR for this commit"
- "commit this", "make a commit", "split these changes into commits"

## The rule

| Intent | Use gavel | Instead of |
| --- | --- | --- |
| PR + CI status | `gavel pr status [<n>] [--logs] [--follow]` | `gh pr view` / `gh run view` / `gh run list` |
| Fix CI from status | `gavel pr status --ai-fix` | — |
| Open a PR (current changes) | `gavel commit -p` | `gh pr create` |
| Open a PR (one existing commit) | `gavel pr create <SHA>` | `gh pr create` |
| List / dashboard PRs | `gavel pr list [--ui]` | `gh pr list` |
| Commit | `gavel commit` | `git add` + `git commit` |
| Pick files to commit | `gavel commit -i` (tree picker, no `git add`) | `git add -p` |
| Split by directory | `gavel commit -A` | manual staging |
| Fixup into a prior commit | `gavel commit --fixup[=<hash>]` | `git commit --fixup` + rebase |

Reserve raw `gh`/`git` for what gavel doesn't cover (e.g. `gh pr merge`,
`gh release`, `git rebase`, branch surgery).

## Checking a PR / CI status

First move when investigating a PR or CI failure:

```bash
gavel pr status                 # current branch's PR + its checks
gavel pr status 123 --logs      # PR #123, including failing-job log tails
gavel pr status --follow        # block until what you filtered on settles
gavel pr status --follow --fail-fast --actions 'CI / Test'   # stop at the first red check
gavel pr status --ai-fix        # send failed checks directly to an agent
```

`gavel pr status --logs` is the go-to for "why is CI red" — it shows the failing
steps and their logs inline. Do not fall back to `gh run view --log`.

## Opening a PR

PR **title, body, and branch name are generated by an LLM** — never hand-roll a
PR body or pass `gh pr create --title/--body`.

```bash
gavel commit -p                 # commit staged/session changes, then push + open a PR
gavel commit -p --auto-merge    # ...and enable auto-merge once checks pass
gavel pr create HEAD            # PR from a single existing commit (isolated worktree)
gavel pr create HEAD --draft --base main
```

See `gavel pr create --help` and the `-p` examples in `gavel commit --help`.

## Committing

`gavel commit` generates a conventional-commit message, runs `.gavel.yaml`
pre-commit hooks, and stages the current agent session's edits by default (no
`git add` needed).

```bash
gavel commit                    # session-scoped commit, AI message, hooks
gavel commit -i                 # interactive tree picker over all changed files
gavel commit -A                 # one commit per top-level directory, split when large
gavel commit -m "chore: bump"   # explicit message, still runs hooks/checks
gavel commit --fixup=<hash>     # squash staged files into an earlier commit
```

`gavel commit --help` documents the full staging model, the gitignore/linked-dep
guards, `--precommit`/`--compat`/`--lint` gates, and the `-p` push/PR path.

## Follow-through

- Use `gavel pr status --ai-fix` for immediate agent repair. When the failure
  needs durable tracking, create a native issue explicitly with `gavel todos create`.
- For running/iterating on tests and linters, see [`gavel-runner`](../gavel-runner/SKILL.md).

## Gotchas

- No `gh pr checks` polling loops — `gavel pr status --follow` blocks until the checks and
  comments you filtered on settle; add `--fail-fast` to return at the first definitive failure.
- With no PR number, `gavel pr status` resolves the current branch's PR, falling
  back to your most recent PR.
- `--logs` only shows output for *failed* jobs; on a green PR it is a no-op.
